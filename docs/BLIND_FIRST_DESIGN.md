# 明途 AI 盲人优先设计说明（总规范的不可妥协部分）

本文件是总规范里“盲人功能不能弱”的落地版，不是新功能清单。
任何新模块先过下面这组检查，过不了就重做，不靠事后补语音播报凑数。

## 检查清单（开发前必答）

1. 用户是否必须看屏幕才能完成核心操作？——必须能只靠语音完成。
2. 用户是否知道系统现在是什么状态、接下来该做什么？——状态必须能语音查询、重复、暂停、取消。
3. 系统不知道时，是否明确说不知道，而不是猜一个方向、距离或步数？
4. 失效时，用户是否知道失效了、影响什么、该怎么办？
5. 危险时，是否优先处理安全问题，而不是先播报普通导航？

## 已落地的硬规则（代码里有测试，不是口号）

- 语音是唯一播报出口：所有模块向语音调度器提交，任何模块不得直接调用 TTS。
- 直行只在确认直线路段时按 3 秒节奏播报；高优先级打断后必须重新确认状态才能恢复，过期提示永不补播。
- 侧方空间无法确认时，绝不给向左/向右迈步指令，只给停下或求助提示。
- 检测置信度 ≠ 空间置信度 ≠ 安全：没检测到障碍不等于前方安全；检测框左右不等于用户左右。
- 语音说完 ≠ 动作完成：播报完成、动作待确认、动作已确认、动作无法确认是四个不同状态。
- 地图显示到了 ≠ 进了门；流程走完了 ≠ 任务成功了；医院前置步骤走完了 ≠ 挂号成功了。
- 紧急求助本地启动，不依赖网络和大模型；永不宣称已联系帮助站，除非有真实回执（当前一律不宣称）。
- 录像保留/删除必须等用户选择；删除只针对本地演示会话，不宣称删了系统外的副本。

## 本阶段新增的统一规则

- 统一事件总线：重复事件不重播，过期事件不执行，旧版本事件不覆盖新状态。
- 统一合同：没有可靠距离时距离字段就是 null，不填一个看起来精确的数字。
- 健康监控：服务降级必须语音告知；没有降级报告时不编造问题，也不伪造健康。
- Skill 门禁：未注册、已禁用、前置条件未满足、高风险无风险确认，一律拒绝执行，不抛异常当成功。

## 仍未验证，必须在材料里诚实写

真实 TTS/ASR、摄像头、GPS、高德、YOLO、红绿灯、精确空间验证、真实道路安全、
真实盲人用户实测——全部未验证。演示视频（如有）必须标注为受控环境演示。
明途不能替代盲杖、导盲犬或专业定向行走训练。
