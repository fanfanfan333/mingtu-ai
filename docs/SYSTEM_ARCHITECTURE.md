# 明途 AI v0.1 系统架构

## 分层（从上到下）

1. 用户交互层：语音输入、语音输出（经调度器）、无障碍操作入口。屏幕只是辅助，不是核心流程。
2. 统一任务控制层：任务状态机、任务上下文、任务取消与恢复、紧急抢占。
3. 感知与环境理解层：摄像头帧、本地 YOLO 检测、目标跟踪、盲道识别占位、OCR（本地优先）。
4. 决策与风险控制层：风险引擎、盲道决策、路线评分、语音调度器。云端大模型只在这里提供候选解释和任务规划，不直接控制每一帧的实时决策。
5. 任务能力层：地图导航、户外行走辅助、目的地入口定位、图书馆室内任务、紧急求助、录像管理。
6. AI 与 Skill 平台层：统一云端网关、三个 v0.1 Skill、医院挂号接口占位。
7. 基础设施层：定位、地图接口、摄像头接口、本地存储、预算记录、测试。

## 关键数据流

摄像头 → 本地检测与跟踪 → 去重后的环境事件 → 风险引擎 → 语音调度器 → 语音播报。

地图 → 候选路线 → 路线评分 → 任务管理器 → 导航状态 → 语音调度器。

用户语音 → 任务意图 → 任务状态机 → Skill → 模块执行 → 结果验证 → 任务状态更新。

云端调用只发生在本地不足的触发点：路线多候选难选、本地 OCR 读不懂、入口多候选、用户问复杂问题。云端调用永不用于连续视频流。

## 状态唯一来源

任务状态只有一个可信来源：任务状态机。任何模块不得私自维护一套“当前导航状态”并覆盖全局状态。语音调度器、风险引擎、导航模块都通过显式状态版本号和事件与任务管理器同步。

## 降级规则

- 云端不可用：继续本地导航与基础规则，不执行依赖云端的复杂任务，明确告知用户能力受限。
- 定位精度不足：不再输出过度精确的方向判断。
- 摄像头被遮挡或失效：提示检查设备位置，不再用旧画面生成新的精确指令。
- 地图服务中断：告知导航服务异常，不假装仍有可靠路线。
- 紧急求助：任何降级都不得影响本地紧急求助入口。
